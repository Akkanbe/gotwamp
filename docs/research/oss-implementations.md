## 1. perfSONAR / Internet2 `owamp` (twampd + twping) — the reference C implementation

Repo: https://github.com/perfsonar/owamp — C, Apache-2.0. Roles: Server + Session-Reflector (`twampd`), Control-Client + Session-Sender (`twping`). No TWAMP Light at all (confirmed by docs, mailing list and code: the reflector verifies the peer address of a *negotiated* session and exits).

### 1.1 Layout and how twampd/twping are built

### 1.2 Ports and constants
- `owamp.h:161-162`: `OWP_CONTROL_SERVICE_NAME "861"`, `TWP_CONTROL_SERVICE_NAME "862"`. twampd listens on TCP 862 by default (`srcnode`); the sample `twampd.conf` comment still says "standard(861) port" — a copy/paste leftover.
- `_TWP_DEFAULT_TEST_TIMEOUT 900` (REFWAIT, `owampP.h:68`); `controltimeout` default 900 for TWAMP (1800 for OWAMP) = SERVWAIT.
- twping test-port range: **man page says default `0` (ephemeral) but code sets 8760-9960** (`owping.c` ~1292: `portspec->low=8760; high=9960`). Sample twampd.conf uses `testports 18760-19960`. pscheduler's defaults file mirrors 8760-9960 for data ports.
- Payload sizes (`api.c:366-406`): sender 14 (open/mixed) / 48 (auth/enc); reflector 41 (open/mixed) / **112** (auth/enc; RFC minimum is 104, perfSONAR uses 7 full AES blocks with HMAC at 96 and padding at 112).
- Default padding when `-s` not given = reflector size − sender size = **27** (open/mixed) or **64** (auth/enc) so both directions have equal payload (`owping.c:1666-1678`).

### 1.3 twampd configuration
`twamp-server.conf` keys parsed in `owampd.c:1003-1200`: `facility`, `loglevel`, `loglocation`, `rootfolly`, `datadir`, `user`, `group`, `verbose`, `authmode` ("AEO" default; `A`uth, `E`ncrypted, `O`pen — twping additionally accepts `M`ixed, RFC 5618), `srcnode [addr]:port`, `testports 0|low-high`, `vardir`, `diskfudge`, `dieby` (30), `controltimeout` (900), `enddelay` (1.0 s), `maxcontrolsessions` (0 = unlimited), `testtimeout` (TWAMP only, 900 = REFWAIT), `pbkdf2_count` (2048). Command-line equivalents: `-a authmode -c confdir -d datadir -e facility -f(root ok) -G group -P portrange -R vardir -S nodename:port -U user -v -Z(foreground)`.

`twamp-server.limits` (parser `policy.c:125-700`): `limit <class> with parent=,bandwidth=,disk=,delete_on_fetch=,allow_open_mode=,test_sessions=` (hierarchical classes; first line is root) and `assign default|net <cidr>|user <identity> <class>`. Semantics: open-mode connections are first checked against `allow_open_mode` of the closest `net` match; authenticated/encrypted connections are classified by `user`. `test_sessions` limits sessions per control connection; `disk`/`delete_on_fetch` are OWAMP-only; `bandwidth` is checked "for one-way sessions" (`policy.c:2365`) — for TWAMP it appears not enforced (**UNVERIFIED**).

`twamp-server.pfs`: identity → hex-encoded passphrase (≤80-char identity), managed with `pfstore(1)`. Keys: PBKDF2-HMAC-SHA1(passphrase, salt from Server-Greeting, count=pbkdf2_count) → AES-128 key; Set-Up-Response token = AES-CBC(IV=0) over challenge(16)‖AES session key(16)‖HMAC-SHA1 key(32) (capi.c:537-560, RFC 4656 §3.1).

### 1.4 Daemon architecture
- Classic **accept/fork** (`owampd.c:540-620`): parent `poll()`s the listening socket, enforces `maxcontrolsessions` (reaping first), creates a `socketpair` to the child (resource-broker IPC), `fork()`s one child per control connection. The parent is the "resource broker" tracking per-class usage.
- Each test session **forks again** inside the control child (`endpoint.c:3983`, `_OWPEndpointInit*`): the child blocks in `sigsuspend` until `SIGUSR1` (= Start-Sessions) or `SIGUSR2` (= Stop-Sessions) and then runs `run_reflector` (server) or `run_tw_test` (client). Timers are `setitimer(ITIMER_REAL)` + `SIGALRM`, sleeping is `nanosleep`.
- Reflector port selection (`endpoint.c:513-560`): requested Receiver Port is honoured only if inside `testports`; otherwise a random port in the range is chosen; if bind fails it walks the range; the actual port is returned in Accept-Session (RFC 5357 §3.5 "alternate port").
- Stop handling (`api.c:810-850`): server side waits `min(session timeout, REFWAIT)` after the Stop-Sessions time before killing the reflector so in-flight packets are still reflected (RFC 5357 §3.5/§4.2).
- Reflector verifies that each test packet comes from the negotiated sender address (`I2SockAddrEqual`, `endpoint.c:2840`) and silently ignores others; packets with wrong length are errors. With `-Z` (zero addresses) the control-connection addresses are used.

### 1.6 Timestamps, NTP sync and Error Estimate (`time.c`)
- `_OWPInitNTP` (lines 108-150): calls `ntp_adjtime()`/`adjtimex()`; logs errors if `STA_UNSYNC` or `STA_NANO` not set ("Make sure ntpd is running").
- `_OWPGetTimespec` (188-300): **`gettimeofday()` in user space** (no `SO_TIMESTAMP*`; confirmed by grep of endpoint.c), then `ntp_adjtime` again: if not `STA_UNSYNC` → `sync=1`, adds `ntp_conf.offset` to the timestamp and uses `ntp_conf.esterror` (µs) as the error; if sync and esterror==0 forces esterror=1 µs. Issue #97 notes chrony isn't recognised by owstats; #98 asks for CLOCK_MONOTONIC_RAW.
- Encoding (`OWPTimespecToTimestamp`, 646-740): NTP 64-bit = unix+`OWPJAN_1970` (2208988800) in the high 32 bits; Error Estimate: `err = usec→Num64` then `while(err >= 0xFF){err>>=1; scale++}; err++ (rounding); multiplier = err&0xFF`; unsynchronised → `scale=64, multiplier=1, sync=0`. Wire: `buf[0] = (sync<<7) | (scale&0x3F)`, `buf[1]=multiplier`; multiplier 0 is invalid (`_OWPEncodeTimeStampErrEstimate`). Decode: `error = multiplier * 2^scale * 2^-32 s` (`OWPGetTimeStampError`).
- Sender sets `IP_TTL`/`IPV6_UNICAST_HOPS` = 255 (`endpoint.c:944-968`); receiver enables `IP_RECVTTL`/`IPV6_RECVHOPLIMIT` and parses cmsg (`recvfromttl`, 1810-1920; note the comment: Linux delivers `IP_TTL` as int, BSD/macOS `IP_RECVTTL` as uchar). DSCP: `IP_TOS` / `IPV6_TCLASS` = (typeP>>24 & 0x3F)<<2 set on **both** sender and reflector sockets from the session's Type-P (`endpoint.c:979-1050`); Type-P with bits outside 0x3F000000 → Accept=`UNSUPPORTED`.

### 1.7 Sender loop (`run_tw_test`, endpoint.c:3089-3760)
Absolute schedule (`start + Σ deltas`), `nanosleep` to the next send; timestamp fetched immediately before `sendto` and re-fetched on `ENOBUFS` retry; after each send it waits for replies with a `setitimer` bounded by min(next send, loss timeout), calling `recvfromttl`; receive timestamp fetched "before ANYTHING else"; `flush_lost()` expires packets older than timeout and writes lost records; replies whose sender seq is below the flushed window are discarded; duplicates detected via `node->hit`; each reply written as a `TWDataRec` to a temp file; statistics are computed afterwards from the file (same code path as `owstats`). Explicitly **does not `connect()` the UDP socket** so ICMP errors don't kill it (comment at 3780).

### 1.8 Reflector loop (`run_reflector`, endpoint.c:2578-3070)
Single blocking loop per session: `recvfromttl` (REFWAIT armed via `setitimer`), take T2, verify peer, decrypt/HMAC-check in auth/enc (invalid HMAC → ignore), build the reply **in place**: `memmove` the sender padding to offset 41/112 (i.e. reuse sender padding, truncating — RFC 5357 §4.2.1 "SHOULD truncate"), zero MBZ, reflector seq `i`, T2, copy sender seq/timestamp/error estimate, Sender TTL from cmsg; then fetch T3 right before `sendto`, with `RETRY` (re-stamp) on `ENOBUFS`. Reply length = max(sender payload, 41/112). Auth: HMAC over cleartext blocks then AES-CBC (IV=0) encryption of 1 block (auth) or 6 blocks (encrypted) with a **separate reply key** `aes_tw_reply_key` (endpoint.c:3839).

### 1.9 Statistics and output (`stats.c`, `IterateSummarizeTWSession` 1239-1556, printing 1890-2560)
Per record: `proc = T3−T2`; `rtt = (T4−T1) − proc`; `fwd = T2−T1`; `bck = T4−T3`; error = sum of the involved Error Estimates; negative fwd/bck sets `clocks_offset` → prints "Directional delays may be inaccurate due to out of sync clocks!". Dups are split into **send duplicates vs reflect duplicates** using the reflector sequence number (1413-1430). Delays are binned into a histogram (`bucketwidth`, default 100 µs, 10-2048 buckets) from which **median and percentiles** are read (bucket index × width); **jitter = P95 − P50** (printed `(P95-P50)`; `PDV` key in -M). TTL → hops = 255−TTL ("send hops = N (consistently)" / "takes K values; min hops/max hops"). Reordering is computed only for OWAMP (comment: "twping won't allow packets to be re-ordered").

Human summary lines: `first:`/`last:`, `%u sent, %u lost (%.3f%%), %u send duplicates, %u reflect duplicates`, `round-trip time min/median/max = a/b/c ms, (err=X ms)` or `(unsync)`, `send time …`, `reflect time …`, `reflector processing time min/max`, `two-way jitter = X ms (P95-P50)`, `send jitter`, `reflect jitter`, `Percentiles:`, `send hops …`, `reflect hops …`.
`-M` keys (`OWPStatsPrintMachine`): `SUMMARY 3.0, SID, FROM_HOST/ADDR/PORT, TO_HOST/ADDR/PORT, START_TIME, END_TIME, [UNIX_START_TIME, UNIX_END_TIME], DSCP, LOSS_TIMEOUT, PACKET_PADDING, SESSION_PACKET_COUNT, SAMPLE_PACKET_COUNT, BUCKET_WIDTH, SESSION_FINISHED, SENT, SYNC, MAXERR, MAXERR_FWD, MAXERR_BCK, DUPS_FWD, DUPS_BCK, LOST, MIN, MIN_FWD, MIN_BCK, MIN_PROC, MEDIAN, MEDIAN_FWD, MEDIAN_BCK, MAX, MAX_FWD, MAX_BCK, MAX_PROC, PDV, PDV_FWD, PDV_BCK, <BUCKETS>…</BUCKETS>, TTL stats (MINTTL_FWD/MAXTTL_FWD etc.)`. Third parties parse these (jsenecal exporter, akprof2000's load test).
`-R` raw format (TWAMP, `owping.c:277-320`): `SSEQ STIME SS SERR SRTIME SRS SRERR STTL RSEQ RSTIME RSS RSERR RTIME RS RERR RTTL` — timestamps as decimal 64-bit NTP integers (`%020PRIu64`), lost = RECVTIME 0, errors as `%g` seconds. `-v`: `seq_no=%-10u fwd_delay=%.3g ms bck_delay=… delay=… proc_delay=… (err=… ms)` or `*LOST*`.

### 1.10 pscheduler `twping` tool ([pscheduler-tool-twping/twping/run](https://github.com/perfsonar/pscheduler/blob/master/pscheduler-tool-twping/twping/run), [enumerate](https://github.com/perfsonar/pscheduler/blob/master/pscheduler-tool-twping/twping/enumerate), [twping_defaults.py](https://github.com/perfsonar/pscheduler/blob/master/pscheduler-tool-twping/twping/twping_defaults.py), [latency validate.py](https://github.com/perfsonar/pscheduler/blob/master/pscheduler-test-latency/latency/validate.py))
Serves tests `latency` and `rtt` (preference 0). Spec→flags: `packet-count→-c`, `packet-interval→-i`, `packet-timeout→-L`, `packet-padding→-s`, `ip-tos→-D`, `data-ports→-P lo-hi`, `ip-version→-4/-6`, `source→-S`, `traverse-nat→-Z`, `ctrl-port` appended to dest. Always runs `twping -R` and parses the 16-field regex. Result JSON (latency schema): `succeeded, packets-sent, packets-received, packets-lost, packets-duplicated, packets-reordered, histogram-latency {bucket: count}, histogram-ttl, max-clock-error (ms = max(src_err+dst_err)), raw-packets[{seq-num, src-ts, dst-ts, src-clock-sync, dst-clock-sync, src-clock-err, dst-clock-err, ip-ttl}]`. Note: for the `rtt` test it computes rtt = (RTIME−STIME)/2^32, i.e. **including** reflector processing time (twping's own RTT subtracts it) — two different "RTT" definitions in the same ecosystem. The `result-format` script derives median/min/max/mean/mode/P25/P75/P95, "P95−P50", "P75−P25", variance, stddev from the histogram. Defaults file: interval .1, count 100, timeout 0 (→ twping default), twampd port 862, data ports 8760-9960.

## 2. Go implementations

### 2.1 tcaine/twamp — https://github.com/tcaine/twamp (MIT, 32★, last commit 2024-10-30)
Client only (Control-Client + Session-Sender), **unauthenticated only** (`client.go`: rejects Modes=0 with "server is not interested", requires bit 1). 7 files / 1356 LOC, `go 1.18`, deps `x/net`, `x/sys`. Packets are structs serialised with `binary.Write/Read` big-endian (`test.go`; `MeasurementPacket` 41 bytes + separate padding slice); timestamps `time.Now()`; `timestamp.go` uses `epochOffset = 0x83aa7e80 s` and **`Fraction: uint32(t.Nanosecond())`** (nanoseconds stored directly, not scaled by 2^32/1e9 — see pitfalls; PR #18 "fix timestamp conversion" touched this). `time.NewTicker` for sending, a second ticker pings the TCP control connection every second; duplicates via `FinishedTimestamp` already set; **TTL hard-coded 87** in the sender; stats min/max/avg/sample-stddev, loss %, dup count, JSON output (`results.go`). CLI `cmd/main.go` (stdlib `flag`): `-count -interval -mode ping|json -port -remote-port -rapid -size -timeout -tos`. No tests. Issues: open #1 local/remote IP, #2 responder, #3 padding→size, #4 auth, #5 encryption, #6 TWAMP-Lite, #10 bytes.Buffer; fixed bugs: #7 hard-coded sender port 6666, #9 short reads, #19 used ReceiverPort as source port, #18 epoch conversion, #24 mode bit check, #25 random padding, #26 deadlock/div-by-zero. Forks: **shmuto/twamp** (continuous mode, remote port, sub-second interval, timestamp fix, IPv6), **halacs/twamp** (adds a `light` package: TWAMP Light *sender* only, same struct codec, `time.Sleep`; 2022), **axamon/twamp** (2019 wrapper). Used by both Prometheus exporters below.

### 2.2 vvidic/go-twamp — https://github.com/vvidic/go-twamp (GPL-3.0, 15★, last commit 2017-09-13)
Single file `twamp-server.go` (588 LOC): **Server + Session-Reflector**, unauthenticated only ("Unsupported setup mode" otherwise). Goroutine per TCP connection, goroutine per reflector; UDP ports allocated by a global `udp_port++` from `-udp-start 2000`, `-listen localhost:2000`. `binary.Read/Write` structs. Error Estimate from **`syscall.Adjtimex()`** (`createErrorEstimate`, line 467: esterror µs → `<<32 /1e6`, shift until <0xFF, but **always sets S=1** even if `STA_UNSYNC`). TTL hard-coded 255; reply padded to request length; random SID and challenge/salt. No DSCP, no tests, no CLI framework. Open PR #1: response length uses buffer size instead of bytes read. Historically the perfSONAR project assigned vvidic to the TWAMP epic (perfsonar/project#1123), so this is a precursor to twampd work.

### 2.3 ncode/twamp — https://github.com/ncode/twamp (Apache-2.0, 0★, 9 commits, last 2026-02-10; actively-developed fork **halacs/twamp_nc** last commit 2026-09-23 "add RFC 5938 individual session mode")
Library (no CLI; `examples/client`, `examples/server`), 94 Go files / **45k LOC**, 63 test files, fuzz tests, `go 1.25.6`, deps prometheus, testify, x/crypto, x/net, x/sys. Roles: Control-Client + Session-Sender (`client/`), Server + Session-Reflector (`server/`). Modes: unauthenticated, authenticated, encrypted, RFC 5618 mixed, RFC 5938 individual session control, RFC 6038 reflect-octets/symmetrical-size (`messages/test_rfc6038.go`, `server/server.go:1463-1700`). Codec: manual `binary.BigEndian` into byte slices with strict length/MBZ checks (`messages/`). Reflector: `ipv4.NewPacketConn(conn).SetControlMessage(ipv4.FlagTTL)` / `ipv6.FlagHopLimit` and `ReadMsgUDP(buf, oob)` → real Sender TTL (`server.go:651-655, 1337-1360`); DSCP via `IPV6_TCLASS` then `IP_TOS` (`common/dscp_linux.go`); `ServerConfig{SERVWAIT, REFWAIT (900 s), PortRange, DSCP, ReceiverAllowlistCIDRs, MaxHMACFailures(100, with reset window)}`; port manager; REFWAIT enforced via 500 ms read deadlines. Client: user calls `SendTestPacket()` in their own loop (no scheduler); `common.MonotonicNow()`; sync bit from `SYS_ADJTIMEX` on Linux (`client/test_session_linux.go`) but **Error Estimate hard-coded `Multiplier=1, Scale=8`** (≈60 ns — meaningless); `common/ttl_unix.go` `GetTTL()` returns a placeholder 255. `common/timestamp.go` handles the 2036 NTP era with a reference-time resolver. Metrics: `sessions_total, packets_sent_total, packets_received_total, packet_loss_total, errors_total, control_messages_total, active_sessions, port_usage, rtt_seconds, jitter_seconds`. Interop harness: docker-compose with `ghcr.io/perfsonar/toolkit:5.0.8` (`test/integration/perfsonar/`). Caveat: very large codebase with a 9-commit history — maturity **UNVERIFIED**; review before depending on it.

### 2.4 akprof2000/twping-go — https://github.com/akprof2000/twping-go (Apache-2.0 + NOTICE, v1.3.1 2026-09-05, last commit 2026-09-23; Russian docs)
A faithful **port of twping** (Control-Client + Session-Sender), 26 files / 4960 LOC, **zero dependencies**, `go 1.24`, 7 test files. ## 6. Design lessons and concrete recommendations for gotwamp

### 6.1 Packet encode/decode
- Use **manual `binary.BigEndian` put/get at fixed offsets into caller-supplied buffers** (perfSONAR pointer layout, ncode `messages/`, snormore, DoubleZero), not `binary.Read/Write` on structs (tcaine/halacs/vvidic): the struct approach allocates per packet, breaks on `time.Time` fields, and makes the 2-byte MBZ / 1-byte TTL tail easy to get wrong (tiny-twamp's 40-byte reflector header, twampy's 38-byte reply).
- Define layout constants per mode exactly as `run_reflector` does: unauth sender `seq@0 ts@4 err@12 pad@14`; unauth reflector `seq@0 ts@4 err@12 mbz@14 rcvts@16 sseq@24 sts@28 serr@36 mbz@38 ttl@40 pad@41`; auth/enc sender `seq@0 ts@16 err@24 hmac@32 pad@48`; auth/enc reflector `seq@0 ts@16 err@24 rcvts@32 sseq@48 sts@64 serr@72 ttl@80 hmac@96 pad@112` (perfSONAR; RFC minimum 104 — accept ≥104 on receive, send 112 for perfSONAR parity).
- Reflector: build the reply in the receive buffer, `copy` the sender padding to the reply padding offset (truncating the highest octets per RFC 5357 §4.2.1), zero MBZ, reply length = max(received length, 41/112). Keep the sender's default padding = 27/64 so sizes are symmetric (twping behaviour); optionally support RFC 6038 reflect-octets/symmetrical size like ncode.
- Keep the sender-side `padding` default random (RFC: SHOULD be pseudo-random, MUST offer all-zeros; tcaine PR #25) with a `--zero-padding` switch.
- STAMP compatibility for the Light reflector: accept sender packets ≥14 bytes, treat extra bytes as padding, reply with ≥41 bytes (RFC 8762 §4.6: a STAMP sender's 44-byte base packet is a valid TWAMP Light sender packet; a STAMP reflector replies symmetric size). Validate seq/timestamp echo on the sender side (DoubleZero does) to drop stray packets.
- Explicitly handle the NTP era: `secs = uint32((unix+2208988800) & 0xFFFFFFFF)` on encode; decode relative to a reference time (ncode `ToTimeWithReference`); fraction = `(nanos<<32)/1e9` (snormore/DoubleZero), never `uint32(nanos)` (tcaine).

### 6.2 Timestamping and Error Estimate
- Take T1 immediately before `WriteTo`/`sendto` (re-stamp on `ENOBUFS` retry like perfSONAR) and T4/T2 immediately after the read in the receiving goroutine (akprof2000, perfSONAR "before ANYTHING else").
- On Linux prefer **kernel RX timestamps**: `SO_TIMESTAMPNS` (DoubleZero, getCUJO) or `SO_TIMESTAMPING` software RX via `golang.org/x/sys/unix` + `UDPConn.ReadMsgUDP(buf, oob)` + `unix.ParseSocketControlMessage`; reuse patterns from `github.com/facebook/time/timestamp` (`EnableSWTimestamps`, `ReadPacketWithRXTimestampBuf`, `ReadTXtimestamp` via `MSG_ERRQUEUE` for software TX stamps, `SO_RXQ_OVFL` drop counter; Linux-only). Keep DoubleZero's sanity rule (kernel ts earlier than user-space send by >100 µs → fall back to user-space) and getCUJO #43 (zero kernel timestamp → fall back). Fallback everywhere else: `time.Now()`.
- Sync bit and error: call `unix.Adjtimex(&unix.Timex{})` (Linux; vvidic/ncode do, akprof2000 doesn't): S = !(status&STA_UNSYNC); error = `esterror` µs (perfSONAR) — some prefer `maxerror`; encode with perfSONAR's shift loop (`while err>=0xFF {err>>=1; scale++}; err++`), never Multiplier 0, S=0 when unknown. Do **not** hard-code (`0x3FFF`, `0x8001`, `Scale=8`) — that is what every hobby implementation does and it makes `MAXERR` meaningless. Expose `--sync/--esterror` overrides (akprof2000) for platforms without adjtimex and for PTP-disciplined hosts.
- TTL: set `IP_TTL`/`IPV6_UNICAST_HOPS` = 255 on sender and reflector sockets; read Sender TTL with `golang.org/x/net/ipv4.PacketConn.SetControlMessage(FlagTTL)` / `ipv6 FlagHopLimit` (ncode) or raw cmsg (akprof2000; note Linux delivers `IP_TTL` as int, BSD `IP_RECVTTL` as byte); if unavailable write 255 (RFC 5357 §4.2), never 64/87.
- DSCP: set `IP_TOS` and (for v6 or dual-stack sockets) `IPV6_TCLASS` = dscp<<2 on sender and reflector from Type-P (RFC 5357 §3.5 "same DSCP MUST be used in reflected packets"); for the Light reflector consider `IP_RECVTOS`/`IPV6_RECVTCLASS` and per-reply TOS via control message (getCUJO reads it; setting per-packet TOS through `ipv4.ControlMessage` on write — **UNVERIFIED** in x/net); optionally mark the control TCP connection too (perfSONAR PR #100, RFC 5357 §3). Accept symbolic names (EF, AF11, CS0…) like twping and twampy's `dscptable`.
- Document host-level requirements: ntpd/chrony sync (twampd man: "clock should be stable"), `net.core.rmem_max` bump for high rates (twamp-rs README), Docker `--network host` (tiny-twamp README).

### 6.3 Scheduler
- Use an **absolute schedule** (`start + cumulative deltas`) and sleep until each deadline; never `time.Ticker` for packet pacing (drops ticks under load and drifts — "Go's standard ticker is not realtime", golang/go#38860, #45632). Implement twping's slot language (`0.1e`, `1f`, `1.0e,0f` pairs) with RFC 4656 §11 AES-CTR exponential deviates seeded by the SID (perfSONAR `schedule.c`, akprof2000 `schedule.go`; verify against `test/owtvec` vectors) so results are comparable with twping/owping.
- Sleep strategy: `time.Sleep(d − spin)` then a short `Gosched` spin (akprof2000 `--spin`, default a few hundred µs); `runtime.LockOSThread()` the sender and receiver goroutines; separate receiver goroutine draining the socket (perfSONAR interleaves recv waits between sends in one process; in Go two goroutines are simpler and akprof2000's fixes show the pitfalls: shared per-packet state needs atomics, and the receiver must `select` on a stop channel so it cannot block forever on a full results channel).
- Runtime knobs to document/apply: `GOMAXPROCS ≥ 2`, `debug.SetGCPercent`/`GOMEMLIMIT` to avoid GC-induced timer delay, Go ≥1.23 on Windows (timer resolution 15.6 ms → 0.5 ms, Microsoft Go blog), optional `chrt -f`/systemd `CPUSchedulingPolicy=fifo` (SCHED_FIFO cannot be set portably from Go — **UNVERIFIED** x/sys support), socket buffers (`SetReadBuffer` 1 MB like tiny-twamp).
- Timeout/termination model from twping: session end = last send + loss timeout; sender waits `enddelay` before Stop-Sessions; reflector keeps reflecting for min(Timeout, REFWAIT) after Stop; declare loss per packet at `send+timeout` (ring buffer / map keyed by seq, flush in order like `flush_lost`).

### 6.4 Statistics
- Compute per packet exactly as `IterateSummarizeTWSession`: `proc=T3−T2`, `rtt=(T4−T1)−proc`, `fwd=T2−T1`, `bck=T4−T3`, `err` = sum of the four error estimates, flag clock offset when fwd or bck < 0; separate send-duplicates vs reflect-duplicates by reflector seq; count sent as unique sender seq numbers (pscheduler does the same from -R).
- Provide the twping summary set (min/median/max per direction + proc min/max, `MAXERR*`, `PDV = P95−P50`, TTL hop counts, percentiles via a histogram with configurable bucket width) **and** the other common jitter definitions clearly named: RFC 3550/1889 EWMA (twampy), mean |ΔRTT| (tiny-twamp, RFC 3393 IPDV style), sample stddev (tcaine/exporters). Make the RTT definition explicit in output (`rtt` vs `rtt_incl_proc`) because pscheduler's rtt test uses T4−T1 without subtracting processing time.
- Output formats: human summary mirroring twping wording; `-M` key/value with the same keys (so jsenecal-style tooling works); `-R` 16-field raw records; `-v` per-packet lines; plus JSON using the pscheduler latency/rtt result schema fields (`packets-sent/received/lost/duplicated/reordered`, `histogram-latency`, `histogram-ttl`, `max-clock-error`, `raw-packets`).

### 6.5 Reflector / server (gotwamp reflector + Light)
- Model: goroutine per control connection + goroutine per session (ncode, vvidic) is the Go equivalent of perfSONAR's fork/fork; keep per-session UDP sockets bound to the negotiated port; enforce `SERVWAIT`/`REFWAIT` (900 s defaults) with read deadlines; stop a session only after min(Timeout, REFWAIT) past Stop-Sessions.
- Port negotiation: honour the requested Receiver Port only inside a configured `testports` range, otherwise pick randomly within the range and return the real port in Accept-Session (perfSONAR); when the sender's Receiver Address/Sender Address are zero (`-Z`) use the control-connection peer; verify test packets by source address (and port when known) and ignore others; treat IPv4-mapped IPv6 control peers by normalising to IPv4 before filling IPVN=4 (perfSONAR encodes IPVN from the socket family — a dual-stack Go listener will see `::ffff:a.b.c.d`).
- Policy: port perfSONAR's limits concepts (classes with `parent`, `allow_open_mode`, `test_sessions`, `net`/`user`/`default` assignment, `maxcontrolsessions`) into a YAML/TOML config; keep a `pfs`-equivalent identity→passphrase store; PBKDF2-HMAC-SHA1 count advertised in Server-Greeting (default 2048); add ncode's HMAC-failure threshold and an allowlist for open mode.
- Light reflector is an amplification vector (41-byte reply for a 14-byte probe, more with padding): rate-limit per source and allow CIDR allowlists (tiny-twamp), optionally require minimum sender size; maintain per-(addr,port) reflector sequence numbers with an idle timeout (twampy 30 s; RFC 8762 stateful mode); default UDP port 862 for STAMP compatibility but allow others (RFC 8545/8762 §4.6); binding 862 needs root or `CAP_NET_BIND_SERVICE` (twamp-gui, teaparty docs) — document systemd `AmbientCapabilities`.

### 6.6 CLI option naming (what twping/twampy users expect)
- Sender CLI: adopt twping's short options verbatim (`-c -i -s -L -D -P -A -u -k -S -B -Z -4 -6 -z -E -F -R -M -v -Q -a -b -n -U`) and positional `testpeer[:port] [server]`; add GNU long forms (`--count --interval --padding --timeout --dscp --port-range --authmode --user --keyfile --source --interface --zero-addr --delay-start --raw --machine --verbose --quiet --percentiles --bucket-width --units --json`). Keep `-i` accepting bare floats (seconds, exponential) and the `e`/`f` slot syntax; twampy/tcaine users expect `--interval` in ms/s and `--count`, `--tos`, `--ttl`, `--padding`, `--do-not-fragment`, `--rapid`, `--json` — support them as aliases where unambiguous (`--tos` as raw TOS byte vs `-D/--dscp`).
- Reflector CLI/config: `-S/--listen [addr]:862`, `-P/--testports lo-hi`, `-a/--authmode AEOM`, `--controltimeout`, `--testtimeout`, `--maxcontrolsessions`, `-Z/--foreground`, `-c/--confdir`; config file keys with the twamp-server.conf names so perfSONAR admins can map them.
- Exit codes like twping: 0 ok, 1 failure, 2 interrupted.

### 6.7 Daemon/CLI architecture for the sender side
- Precedents: lopa (REST), pscheduler (REST + plugin JSON), tiny-twamp (pull config, push results), stamp-suite (loopback HTTP control API + Prometheus). Recommendation: `gotwampd` owns long-running "sessions" (IP SLA probes: target, interval schedule, count/continuous, padding, DSCP, auth) defined in a YAML file and mutable via a **local gRPC-over-Unix-socket API** (no auth problem, easy CLI) with an optional HTTP/JSON gateway; `gotwamp` CLI = `twping`-compatible one-shot mode that embeds the library when no daemon is needed (akprof2000's `twping.Run(ctx, args, writer)` is a good embeddable shape) plus `gotwamp session add/list/show/stop` and `gotwamp results <id> [-M|-R|--json]` against the daemon. Expose Prometheus (`/metrics`) with labels `source,target,dscp,session` and the metric set of the exporters (`rtt_seconds` summary/histogram, `probes_lost_total`, `probe_success`, per-direction min/median/max/pdv, `max_clock_error_seconds`, `clock_synchronized`). Keep raw per-packet records in a bounded ring per session so `-R` output and pscheduler-style `raw-packets` can be produced after the fact (twping writes them to a file first and computes stats from the file — the same two-stage design works for a daemon).
- Reuse one control connection per target for repeated bursts (adammmmm caches sessions) but implement per-step control deadlines (akprof2000 v1.2.0: a silent server kept clients hung forever and exhausted ports).

### 6.8 Testing strategy (seen to work)
- RFC 4656 Appendix exponential-deviate test vectors (`owtvec`); byte-exact golden tests of every control/test message; fuzz the decoders (snormore, ncode, DoubleZero).
- In-process reflector with fault injection: drop every Nth, duplicate every Nth, add processing delay (akprof2000) → asserts loss/dup/proc stats.
- Interop CI against the real reference: Docker image building perfSONAR owamp from source (akprof2000 `testing/Dockerfile.owamp`, also needs `perfsonar/i2util`) or `ghcr.io/perfsonar/toolkit` (ncode); run `twping` against gotwamp's reflector and gotwamp's sender against `twampd` in all four modes; diff `-M` output field by field. Also test against `nokia/twampy responder` (TWAMP Light) and `stamp-suite`/`teaparty` (STAMP) for the Light path.
- Load test at 1-5 kpps with and without 1000-byte padding (akprof2000 `loadtest.sh`; perfSONAR issue #104 shows the C reflector dropping at this rate).

## 7. Pitfalls and bugs observed across implementations (with sources)

1. **NTP epoch/fraction conversion**: tcaine stored nanoseconds directly in the fraction field (`timestamp.go`, fixed by PR #18 only in forks); twamp-gui #2 "fraction part not accurate"; emirica #5 NTP format/sequence endianness. Use `frac=(nanos<<32)/1e9`, `secs=unix+2208988800` truncated to 32 bits; resolve the 2036 era with a reference time (ncode `common/timestamp.go`). Y2K38/overflow in timespec arithmetic bit getCUJO (#42, #53).
2. **Error Estimate**: hard-coded constants (twampy 0x3FFF/0x0001, emirica 0x8001, ncode Scale=8, tiny-twamp S-only), byte-order bug (twamp-gui #13), S=1 regardless of sync (vvidic), Multiplier=0 invalid (RFC 4656 §4.1.2; perfSONAR encoder refuses). Derive from adjtimex; follow perfSONAR's shift/round algorithm.
3. **Byte order of control fields**: Mode in host order (emirica #8, Cisco rejects), Padding Length not `htonl` (emirica #10, Juniper rejects), Stop-Sessions must carry Number of Sessions (twamp-gui #9), SID must be server-generated random (twamp-gui #12, vvidic commit).
4. **Reflector packet layout**: missing MBZ/TTL bytes (twampy 38-byte reply, issue #17; tiny-twamp TTL at offset 39), padding not mirrored/truncated per spec (twamp-gui #5, twampy #17), extra non-standard fields (getCUJO `sender_tos`), non-RFC "Light" formats that cannot interoperate (snormore 24 B, DoubleZero 48 B). Minimum sender padding 27/56 (RFC 5357 §4.1.2, RFC 6038 §3) if symmetric sizes are wanted.
5. **TTL handling**: senders not setting TTL 255 and reflectors inventing values (tcaine 87, tiny-twamp 64) corrupt hop counts; RFC 5357 §4.2 requires 255 when the real TTL cannot be read; Linux vs BSD cmsg types differ (perfSONAR `recvfromttl` comment); Windows cannot read TTL (akprof2000 prints "TTL not reported").
6. **DSCP**: reflector must copy the session DSCP (RFC 5357 §3.5); twampy DSCP bug (PR #16); IPv6 needs `IPV6_TCLASS`; setting DSCP may need root (twampd `-f`/`rootfolly` man text); perfSONAR added DSCP on the control connection only in 2024 (#100). Default TOS 0x88 in twampy surprises users.
7. **IPv6 / IPv4-mapped addresses**: emirica #19 (`msg_namelen` always IPv4), twamp-gui #6, twampy #5 (100 % loss on IPv6), perfSONAR #103/#105/#106 (confusing getaddrinfo errors). Go dual-stack listeners present `::ffff:` peers — normalise before setting IPVN and addresses in Request-TW-Session, and bind test sockets with the same family as the control connection.
8. **Ports**: 862 needs root/`CAP_NET_BIND_SERVICE` (twamp-gui README, teaparty); sender used ReceiverPort instead of SenderPort (tcaine #19, twamp-gui #4); hard-coded 6666 (tcaine #7); reflector may return an alternate port that the sender must honour (RFC 5357 §3.5, perfSONAR `endpoint.c:513-560`); twping's documented vs actual `-P` default differ (0 vs 8760-9960); pscheduler requires a ≥2-port range.
9. **NAT/firewalls**: UDP reflected to the sender's negotiated address fails behind NAT (twamp-gui #15/#16); perfSONAR's `-Z` zero-address option and PAT handling (#99/#100) exist for this; the reflector's "Receiver Port" is chosen by the server so firewalls must allow the `testports` range.
10. **Modes=0 and mode negotiation**: Modes=0 in Server-Greeting means "go away" (RFC 4656 §3.1; tcaine errors out, perfSONAR "No Common Modes" closes); bit tests must be `mode & 1` not `== 1` (tcaine #24); mixed mode bit (RFC 5618) must be understood by servers advertising it; truncated greetings crash naive parsers (twampy #1).
11. **SERVWAIT/REFWAIT and idle closes**: servers that close "idle" control connections during a test (twamp-gui #25) violate RFC 5357 §3 (monitoring suspended between Start- and Stop-Sessions); reflectors must keep reflecting for Timeout after Stop-Sessions (perfSONAR `api.c:825-850`); clients must bound every control step (akprof2000 v1.2.0).
12. **Authenticated/encrypted correctness**: HMAC over cleartext then encrypt; auth = 1 block ECB-equivalent, encrypted = 2 sender / 6 reflector blocks CBC with IV 0; reflector uses a distinct reply key (perfSONAR `aes_tw_reply_key`); PBKDF2 count from Server-Greeting; perfSONAR's 112-byte auth reply vs RFC's 104 minimum — accept both.
13. **Sequence numbers / duplicates / reordering**: distinguish send vs reflect duplicates via reflector seq (perfSONAR; issue #102 shows user confusion); discard replies for already-flushed sequence numbers; reflector seq must reset per session (twampy per-address 30 s timer); wrap at 2^32 is only a concern for continuous sessions — use `uint32` arithmetic and session restarts.
14. **Timing in Go**: `time.Ticker` drops ticks and drifts under load; timers are delayed by CPU-bound goroutines and GC (golang/go#38860, #45632); Windows timer granularity was 15.6 ms before Go 1.23 (now ~0.5 ms); busy-wait loops burn 100 % CPU (twampy #18) — use sleep+short spin. Kernel RX timestamps remove most user-space jitter (DoubleZero benchmark, getCUJO).
15. **Throughput**: reflectors dropping packets at ≥1 kpps with large payloads (perfSONAR #104); raise socket buffers, avoid per-packet allocation, consider `recvmmsg` (janej2013 demo) for collectors.
16. **Output/semantics drift**: "RTT" with or without reflector processing time (twping vs pscheduler rtt), "jitter" meaning P95−P50 (twping), RFC 1889 EWMA (twampy), mean |Δ| (tiny-twamp) or stddev (exporters) — name them explicitly.
17. **Clock sync detection**: ntp_adjtime/adjtimex only reflects ntpd/chrony kernel discipline (perfSONAR #97 chrony note); negative one-way delays confuse users (emirica #20) — print perfSONAR's "Directional delays may be inaccurate" warning and keep RTT independent of sync.
18. **Docs vs code**: twping man page default `-P 0` vs code 8760-9960; twampd.conf comment "861"; twping `-n` default 'm' vs man "Unset" — keep generated help authoritative.
