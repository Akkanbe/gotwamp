# TWAMP vendor survey — gap-fill: Nokia SR Linux, Arista EOS, Nokia SR OS, Huawei, SONiC/VyOS/OpenWrt, containerlab

Scope note: Cisco and Juniper deliberately excluded (covered elsewhere). "UNVERIFIED" marks anything I could not confirm from a primary source within the tool budget. Dates: research done 2026-10-03.

## 1. Nokia SR Linux (free container `ghcr.io/nokia/srlinux`)

**Verdict: SR Linux DOES support TWAMP — as a Full-TWAMP server + session-reflector, as a STAMP session-reflector, and (24.7+) as a STAMP session-sender via OAM-PM IP sessions and IGP link-measurement. It has no TWAMP control-client and no "TWAMP Light"-named sender; the sender side is STAMP (RFC 8762), which is wire-compatible with TWAMP Light unauthenticated test packets.**

Sources: SR Linux 24.7 OAM and Diagnostics Guide (HTML) https://documentation.nokia.com/srlinux/24-7/books/oam/oam_fault_and_performance_tools_and_protocols.html (sections "Configuring a TWAMP server", "Configuring STAMP session reflector", "Interoperability of STAMP and TWAMP Light", "Displaying TWAMP/STAMP statistics"); PDF https://documentation.nokia.com/srlinux/24-7/books/pdf/OAM_and_Diagnostics_Guide_24.7.pdf; YANG models https://github.com/nokia/srlinux-yang-models (paths below from tag v25.3.1 unless noted).

Release history (from YANG tags via GitHub API; release notes themselves not fetched — treat as "first appears in the model"):
- `srl_nokia-twamp.yang` (TWAMP server/reflector): present in the earliest tag I checked, **v22.11.1** (so introduced in 22.x or earlier; exact release UNVERIFIED).
- `srl_nokia-stamp.yang` (STAMP session-reflector): first appears **v23.7.1**.
- `srl_nokia-tools-twamp.yang` (clear statistics): v23.10.1.
- **v24.7.1**: models moved to `srl_nokia/models/twamp/` and gained `srl_nokia-oam-pm-ip.yang` (STAMP session-sender), `srl_nokia-link-measurement.yang` (dynamic IGP link delay via STAMP), `srl_nokia-ippm-source-udp-pool.yang`. Still present in v24.10.1, v25.3.1, v25.7.1.

TWAMP Full server (`/oam/twamp/server/network-instance[name]`, feature flag `srl_nokia-feat:twamp`):
- YANG `must` error text: "TWAMP server is only supported on default network instance".
- `admin-state` default disable; `servwait` 1..604800 s default 900; `control-packet-dscp` default CS7 (doc example uses 12); `allow-ipv6-udp-checksum-zero` default false; `enforce-test-session-start-time` default true; `maximum-connections` 1..64 default 32; `maximum-sessions` 1..128 default 32; `client-connection <prefix>` list with per-prefix `maximum-connections`/`maximum-sessions` (same ranges/defaults). Clients whose source does not match a `client-connection` prefix are dropped (state counter `no-client-prefix-match`).
- Doc example: `oam { twamp { server { network-instance default { admin-state enable  servwait 900  control-packet-dscp 12  enforce-test-session-start-time true  client-connection 192.15.20.9/32 { maximum-connections 32  maximum-sessions 32 } } } } }`.
- Modes (doc): "unauthenticated server", plus "individual session control (mode bit 4: value 16)", "reflected octets (mode bit 5: value 32)", "symmetrical size test packet (mode bit 6: value 64)". No authenticated/encrypted mode. Doc also states test packets carry a "minimum 27 bytes padding for symmetry".
- State list `session-reflector/test-session` has `reflector-udp-port` with YANG range **`862 | 49152..65535`** — i.e. the Receiver Port a client requests in Request-TW-Session must be 862 or an ephemeral port (rejection counter names: `udp-port-in-use`, `duplicate-session`, `bad-type-p`, `padding-too-big`, `non-zero-mbz-value`, `non-zero-session-sender-sid`, `timeout-too-large`, `non-local-ip-destination`, `invalid-ip-address-version`, `client-source-ip-unreachable`, `refwait-timeout`). Test-packet drop counters: `incorrect-packet-size`, `incorrect-source-address`, `arrived-before-start-time`, `no-start-sessions`, `invalid-error-estimate`, `invalid-server-octets`, `invalid-symmetric-mbz`. Control drop counters include `unsupported-mode`, `invalid-hmac`, `non-zero-sid-in-client-control-message`, `incorrect-stop-session-count`. State also exposes `test-packet-dscp`, `last-sequence-number-transmitted/received`.
- Show: `info from state oam twamp`, `tools oam twamp ... clear` (24.x).

STAMP session-reflector (`/oam/stamp/session-reflector/network-instance[name]`, feature `srl_nokia-feat:stamp`):
- `admin-state` default disable; `udp-port` range **`862|64364..64373`**, default **862**; IPv4/IPv6 `prefix` list ("supports a prefix list which filters based on IPv4 or IPv6 addressing"; counter `prefix-match-failure`); a reflector timeout leaf 1..604800 s default 900 (leaf name UNVERIFIED, likely refwait). Doc: "The reflector is stateful and uses the tuple SIP, DIP, SP, DP, or SSID to identify individual STAMP test sessions"; not restricted to the default network-instance ("For each routed network instance...").
- Interop rule (doc "Interoperability of STAMP and TWAMP Light"): the reflector decides STAMP vs TWAMP Light by packet length and whether byte 45 matches the TLV-flags pattern `100xxxxx`: "If found, the packets are processed as STAMP packets. If not found, the packet is assumed to be a TWAMP Light padded packet"; a TWAMP Light packet that "mistakenly matches the 100xxxxx pattern" has its padding parsed as TLVs. Reply copies Sequence Number, Timestamp and Error Estimate from the request (RFC 8762 behaviour).

STAMP session-sender (24.7+): OAM-PM IP session (`srl_nokia-oam-pm-ip.yang`, features `oam-pm` and `oam-pm-ip`): `destination-udp-port` 1..65535; `source-udp-port` `0 | 64374..64383` default 0 (0 = auto from the IPPM source pool 64374..64383); `dscp` default CS6; `forwarding-class`/`profile` (qos feature); `ttl` 1..255 default 255; `stamp { admin-state (default disable); pad-size "0 | 3..9502" default 0; interval default 1s }`. Link-measurement (`srl_nokia-link-measurement.yang`): `stamp { destination-udp-port 1..65535 default 862; source-udp-port 0|64374..64383; dscp CS6; ttl default 1; ipv6-destination-discovery }`.

Container vs hardware: the OAM guide text I could read contains **no platform-support statement**, and all four feature sets are gated by `if-feature` flags (`twamp`, `stamp`, `oam-pm-ip`, `link-measurement`) that are enabled per platform at runtime. **Whether they are active on the container image is UNVERIFIED** — check with `info from state system features` on a running `ghcr.io/nokia/srlinux` (containerlab note: in "license-less mode, the datapath is limited to 1000 PPS and the sr_linux process will restart once a week" — https://containerlab.dev/manual/kinds/srl/). DSCP/TTL reflection behaviour of the SR Linux reflectors: UNVERIFIED (doc only exposes `control-packet-dscp` and per-session `test-packet-dscp` state).

The article body sits behind an arista.com login (my fetch returned the login page), so **CLI syntax is UNVERIFIED** here — read the TOI with your account.
- EOS User Manual, IS-IS chapter (https://www.arista.com/en/um-eos/eos-is-is, section "Dynamic Link Delay using TWAMP Light"): two independent modes — **Active** ("device initiates sending probe packets and receives reflected packets with a timestamp to compute link-delay") and **Reflector** ("device receives the probe packet, adds the timestamps, and sends it back"); "Same interface can be in Active mode and Reflector mode simultaneously" and you must "Configure different UDP ports for each mode"; advertises unidirectional average, min/max delay and delay variation; **"Only supports IPv4 probe packets"**.

## 3. Nokia SR OS (7750 SR / 7250 IXR; vSIM needs a license)

Sources: TWAMP Light Session-Reflector (SR OS 22.7) https://infocenter.nokia.com/public/7750SR227R1A/topic/com.nokia.OAM_Guide/twamp_light_session_reflector.html; TWAMP Light overview (22.5) https://infocenter.nokia.com/public/7750SR225R1A/topic/com.nokia.OAM_Guide/two-way_active_-ai9exgsu8h.html; MD-CLI `test-oam` reference (21.7) https://infocenter.nokia.com/public/7750SR217R1A/topic/com.sr.mdcli/html/test-oam-test-oam_0.html; TWAMP Light commands with ranges (7210 SAS 22.9, same CLI model) https://infocenter.nokia.com/public/7210SAS229R1A/topic/com.nokia.DEK_OAM_Guide/twamp_light_com-d478e45464.html; STAMP/TWAMP Light PDU differences https://infocenter.nokia.com/public/7750SR227R1A/topic/com.nokia.OAM_Guide/ip_performance_twamp.html.

TWAMP Light reflector (`configure router twamp-light reflector` / `configure service vprn <id> twamp-light reflector`; classic `config>router>twamp-light>reflector udp-port <n> create`):
- `udp-port`: "a restricted, reserved UDP port range that must adhere to a range of **862, 64364 to 64373**" (quoted on both the 22.5 and 22.7 pages).
- `prefix <ip-prefix/len>`: required allow-list; "If the source IP address in the TWAMP Light packet arriving on the responder does not match a configured IP address prefix, the packet is dropped." IPv4 and IPv6 prefixes.
- `configure test-oam twamp twamp-light inactivity-timeout`: range **10..100 s, default 100** — "Time to maintain stale state on the session reflector" (defines "the amount of time the TWAMP-Light Session-Reflector maintains individual test session in the absence of the arrival of test packets").
- `allow-ipv6-udp-checksum-zero`: accept IPv6 test packets with UDP checksum 0 (default: rejected).
- Stateful: "The TWAMP-Light Session-Reflector is stateful and supports unidirectional synthetic loss detection" (i.e. it keeps per-session reflector sequence numbers; no stateless mode documented).
- Timestamps: "responds using the timestamp format that is indicated in the test packet from the Session-Sender" and "replies using the same format for timestamp two (T2) and timestamp three (T3)" (NTP or PTP per the Z bit).
- DSCP/CoS: "CoS parameters communicated over the TWAMP control channel are replaced with a reply-in-kind approach. The reply-in-kind model reflects back the received CoS parameters" — the reflector copies the received DSCP into the reply. TTL in the reply: UNVERIFIED.
- Addressing: "TWAMP Light is supported on deployments that use IPv4 or IPv6 addressing"; "All IP addressing must be unicast. IPv6 addresses cannot be a reserved or a link local address."
- Packet-size validation: no minimum/maximum stated beyond the symmetric-size design ("The pad size, the size of the all 0's pad, can be configured to ensure that the TWAMP packet is the same size in both directions"); UNVERIFIED whether undersized packets are dropped.
- STAMP: 22.7 doc covers PDU padding/TLV differences and "backward compatibility" between TWAMP Light and STAMP on the reflector (a `type twamp-light|stamp` knob is UNVERIFIED).

TWAMP Full server (`configure test-oam twamp server`; classic `config>test-oam>twamp>server`), MD-CLI 21.7 defaults:
- `admin-state` default disable; `prefix <ipv4|ipv6-prefix>` (max 100) each with `description`, `max-connections` 0..64 default 32, `max-sessions` 0..128 default 32 (classic names `max-conn-prefix` / `max-sess-prefix`, default 32 each); server-wide `max-connections` 0..64 default 32 and `max-sessions` 0..128 default 32; `inactivity-timeout` **60..3600 s default 900** ("System wide inactivity timeout for each TWAMP server control connection"); `ref-inactivity-timeout` default 900 s (classic CLI; from search snippet of the OAM CLI reference — UNVERIFIED range). Server/reflector roles only; SR OS has no TWAMP control-client. TCP 862 is the standard control port (not a configurable item found). Modes: unauthenticated only (UNVERIFIED).

OAM-PM TWAMP Light session (`configure oam-pm session <name> ip ... twamp-light`), ranges from the 7210 page (7750 identical unless noted):
- `dest-udp-port` **1..65535** (must be 862/64364–64373 when the peer is a Nokia reflector); `source-udp-port` **64374..64383** (also the only values accepted by the SR OS sender; same pool as SR Linux).
- `interval`: 7210 platforms list 100/1000/10000 ms or 100..1000 step 100 + 10000; 7750 SR range UNVERIFIED (believed 100..100000 ms).
- `pad-size` **0..2000 octets, default 0**; `pattern` (all-zeros/all-ones) UNVERIFIED; `dscp` (name) and `fc {be,l2,af,l1,h2,ef,h1,nc}`; `profile in|out` default out; `ttl` **1..255 default 255**; `record-stats delay|loss|delay-and-loss` default **delay** ("default collection routine includes delay field processing only"); `test-id` 0..2147483647; `test-duration` 1..86400 s; `allow-egress-remark-dscp`: UNVERIFIED.

## 4. Huawei NE/CX (NQA TWAMP and TWAMP Light) — from the locally saved doc text

Sources (saved text): NE20E-S V800R022C00SPC600 Configuration Guide, "TWAMP Light Configuration" https://support.huawei.com/enterprise/en/doc/EDOC1100282195/5087c43e/twamp-light-configuration; NetEngine 8000 F8 V800R022C00SPC600 "TWAMP Configuration" https://support.huawei.com/enterprise/en/doc/EDOC1100279002/5fdc54b3/twamp-configuration; "Understanding TWAMP Light" https://support.huawei.com/enterprise/en/doc/EDOC1100270080/bd19d3a6/understanding-twamp-light; command-reference index. TWAMP Light:
- Responder: `nqa twamp-light` → `responder` → `test-session <id> { local-ip <v4> remote-ip <v4> | local-ipv6 <v6> remote-ipv6 <v6> } local-port <p> remote-port <p> [ vpn-instance <name> ] [ interface <if> | link-bundle ... ]` (local = reflector side, remote = sender side). Rules: "The IP address configured for a test session must be a unicast address. The UDP port number of the Responder must be a port number not in use." The reflector session is a **full 4-tuple (sender IP + port, reflector IP + port)**; "port number, VPN, and interface parameters cannot be modified. To modify these parameters, delete the session and reconfigure it."
- Sender (view is `sender`, shown as `client` in older configs/command names, e.g. `nqa twamp-light client test-session 1 ...`): `test-session <id> { sender-ip <v4> reflector-ip <v4> | sender-ipv6 <v6> reflector-ipv6 <v6> } sender-port <p> reflector-port <p> [ vpn-instance <name> ] [ dscp <0-63> | padding <len> | padding-type <type> | description <d> ] *` (also a `link-bundle-interface` form, `test-session <id> bind interface <if>`, and `one-way delay-measure enable`, which needs PTP). "After a test session is configured, all parameters, except description, cannot be modified."
- Start/stop: `test start test-session <id> { duration <s> | packet-count <n> } [ period { 10 | 100 | 1000 | 30000 } ] [ time-out <s> ]`; `test start-continual test-session <id> [ period {10|100|1000|30000} ] [ time-out <s> ]`; `test start-regular test-session <id> [ regular-time <t> ] [ packet-count <n> ] [ time-out <s> ]`; `test stop { all | test-session <id> }`. Period unit is ms (10 ms probing supported).
- Defaults seen in `display` output when not configured: `Mode : unauthenticated`, `DSCP : 0`, `Padding Length : 128`, `Padding Type : 00`, `Period Time(in millisecond) : 10`, `Time Out(in second) : 5`.
- Multiple sessions to one reflector port are distinguished by sender port: example "test-session 1 ... sender-port 1025 reflector-port 1025 dscp 3" and "test-session 2 ... sender-port 1026 reflector-port 1025 dscp 6". Allowed UDP port ranges (e.g. 1025–65535): **UNVERIFIED** — not stated in the config guide text; examples use 1025, 1026, 2001, 2010, 65530.
- IPv6: supported (`-ipv6` keywords; "Example for Configuring TWAMP Light IPv6 Functions"); note "ensure that the length of the IPv6 packets to be sent is smaller than the smallest MTU ... Otherwise, packets are discarded."
- Stats/show: `display twamp-light test-session [ verbose | <id> ]` (fields: Session ID, State, Type continual/…, Sender IP/Port, Reflector IP/Port, Mode, DSCP, Padding Length/Type, VPN Instance, Link-Bundle Interface, Last Start/Stop Time, Regular Time(min), Period Time(ms), Time Out(s), Duration Time(s), Packet Count); `display twamp-light statistic-type { twoway-delay | twoway-loss | oneway-delay } test-session <id>` (Average/Maximum/Minimum Delay, Jitter, TxDelay/RxDelay, TxJitter/RxJitter, Loss Count/Ratio, RxError Count/Ratio, per-index tables); `display twamp-light responder test-session [verbose|id]`; `reset twamp-light statistics`; alarm thresholds `test-session <id> upper-limit … lower-limit …` for delay/jitter/loss; telemetry sensor-group `twamp`; BGP-LS export of a session id (`bgp-twamp-light-test-session-id`).

TWAMP Full (NE8000 F8): Huawei acts as **Server + Session-Reflector only**; the guide assumes a third-party "control-client and session-sender [that] comply with relevant standards" (there is a `client` command in the command index, role support as control-client UNVERIFIED).
- `nqa twamp` → `server` → `tcp listen-mode { any-ip | assign-ip }`, `tcp listen-address <ip>`, `tcp port <port> [ all | vpn-instance <name> ]` ("the default port number is 862"; examples use 65530), `control-session inactive <time-out>` (command name `ctrlsess-inactive-timeout`), `client acl { <basic> | <adv> | <name> }` (`client-acl`); `reflector` → `test-session inactive <time-out>` (`testsess-inactive-timeout`), example value 600.

## Interop pitfalls / design requirements for gotwamp

1. **Reflector listening port must be configurable, including 862 and the Nokia-specific range 64364–64373**: SR OS reflectors only exist on 862/64364–64373 and SR Linux STAMP reflectors default to 862 — gotwamp's sender must allow any destination port; gotwamp's reflector should allow binding to these so Nokia senders (which default to dst 862) can hit it.
2. **Source UDP port**: Nokia SR OS/SR Linux senders use 64374–64383 as source ports; SONiC restricts ports to 862/863/1025–65535; Huawei and SONiC reflectors are provisioned per exact (sender IP, sender port, reflector IP, reflector port) 4-tuple — gotwamp's sender must support a **fixed, configurable source port** and must keep it stable for the session lifetime (no ephemeral re-bind per packet).
3. **Source-prefix allow-lists are the norm** (Nokia `prefix`/`client-connection`, Huawei `client acl`, SONiC 4-tuple): gotwamp's reflector should support a source-prefix ACL and count drops (`incorrect-source-address` / `prefix-match-failure` equivalents); expect silence (not ICMP) from vendor reflectors when not whitelisted.
4. **STAMP/TWAMP Light coexistence**: Nokia reflectors sniff byte 45 (first byte after the 44-byte base) for the STAMP TLV flag pattern `100xxxxx`. gotwamp's Light sender should pad with **all zeros** (RFC 8762 also expects zero padding) and never emit padding whose first byte has the top bits `100`; gotwamp's reflector must accept 44-byte unpadded STAMP-style requests from SR Linux (pad-size default 0) and ideally parse/skip RFC 8972 TLVs.
5. **Timestamp format**: SR OS replies "using the same format indicated in the test packet" (NTP vs PTP via the Error Estimate Z bit); SONiC can send PTP format. gotwamp's reflector should honour Z and reply in kind; the sender should expose a format choice.
6. **Symmetric size / minimum padding**: SR Linux's Full-TWAMP server documents "minimum 27 bytes padding for symmetry" and rejects `padding-too-big`/`incorrect-packet-size`; SR OS and Huawei default to symmetric sizing (Huawei default padding 128). gotwamp's Request-TW-Session should request Padding Length ≥ 27 and the reflector should reply with the same total size as the request.
7. **Stateful reflectors with short inactivity timers**: SR OS keeps per-session state for 10–100 s (default 100), SR Linux/Huawei 900/600 s class timers; gotwamp's reflector sequence numbers should be per-(4-tuple) and expire; the sender should tolerate reflector sequence resets after idle gaps.
8. **DSCP reply-in-kind**: SR OS copies the received DSCP into the reply; SONiC/Huawei default DSCP 0, TTL 255. gotwamp's reflector should copy DSCP (and set TTL 255), and the sender should let DSCP/TTL be set per session and record the received values for mismatch detection.
9. **Full-TWAMP control**: all surveyed servers are **unauthenticated-only** (SR Linux explicitly; SR OS/Huawei show only unauthenticated), SR Linux additionally advertises mode bits 16/32/64 (individual session control, reflected octets, symmetric size); SR Linux rejects non-zero MBZ, non-zero SID in Request-TW-Session, `timeout-too-large`, non-local receiver address, receiver ports outside 862/49152–65535, and (by default) test packets arriving before the session start time (`enforce-test-session-start-time`). gotwamp's client must zero all MBZ/SID fields, request receiver ports in that range, send Start-Sessions promptly, and handle Server-Greeting mode masks with extra bits set; gotwamp's server should enforce per-prefix connection/session caps (32/32 is the common default) and a ~900 s control inactivity timer.
10. **Send-rate expectations**: Huawei probes at 10 ms periods, SONiC at 10/100/1000 ms, SR OS 100 ms+; the SR Linux free container caps datapath at 1000 PPS — keep interop test rates ≤ 10 pps per session on the container.
11. **IPv6**: SR OS/SR Linux reject link-local/reserved IPv6 addresses and drop UDP-checksum-zero IPv6 packets unless `allow-ipv6-udp-checksum-zero` — gotwamp must always compute IPv6 UDP checksums and use global addresses.
12. **Lab plan**: realistic free interop targets are SR Linux (TWAMP Full server + STAMP reflector/sender, pending feature-flag check on the container), VyOS/perfSONAR (TWAMP Full server, twping as a reference client) and SONiC-VS (if its image carries the twamp container). cEOS-lab offers nothing to test against; SR OS and Huawei need licensed/hardware targets.
